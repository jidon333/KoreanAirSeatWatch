# Korean Air Seat Watch

대한항공 공식 웹 화면을 사용하는 Windows 마일리지 좌석 조회·알림 도구입니다. 대한항공과 제휴한 공식 앱은 아닙니다. 항공편 예약·대기 신청·결제는 수행하지 않습니다.

## 설치와 실행

Windows, Python 3.12, Google Chrome이 필요합니다.

```powershell
.\Setup.ps1
.\Start-SeatWatch.cmd
```

출발·도착 공항 코드, 출발일, 좌석 등급을 입력한 뒤 **조건 추가**를 누릅니다. 로그인은 앱이 연 대한항공 공식 창에서 합니다. 비밀번호는 앱에 입력하지 않습니다. 전용 Chrome을 닫았으면 다음 조회에서 다시 엽니다.

현재 지원: 편도, 로그인한 회원 1명, 여러 노선·날짜·등급 조건의 순차 조회. 가까운 날짜 함께 조회를 항상 체크하고 입력한 날짜의 실제 항공편을 확인합니다. 오류를 매진으로 처리하지 않고 조건별 마지막 정상 결과와 확인 시각을 유지합니다.

## 여러 조건 순차 조회

1. 위 입력란에서 조건을 정하고 **조건 추가**를 누릅니다. 같은 조건은 중복 등록하지 않습니다. 이전 버전에서 쓰던 조건은 처음 실행할 때 자동으로 목록에 옮깁니다.
2. **전체 조회 간격**을 정합니다. 기본 5분이며 5~60분 사이의 정수를 입력할 수 있습니다.
3. **순차 자동 확인**을 누릅니다. 목록 순서대로 조건 하나를 조회하고, 완료 후 설정한 간격만큼 기다렸다가 다음 조건을 조회합니다. 마지막 조건 다음에는 첫 조건으로 돌아갑니다.
4. 목록의 **다음** 표시와 다음 조회 시각으로 진행을 확인합니다. 목록에서 조건을 선택하면 아래에 해당 조건의 마지막 정상 항공편 결과가 나타납니다.
5. 조건이나 간격을 바꾸려면 **자동 확인 중지**를 누릅니다. 목록에서 조건을 골라 입력란을 바꾼 뒤 **선택 조건 수정**을 누르거나, **삭제**로 제거합니다. 다시 시작하면 저장된 순서부터 이어갑니다.

예를 들어 조건 3개·간격 5분이면 A → 5분 대기 → B → 5분 대기 → C → 5분 대기 → A 순서입니다. 각 조건은 약 15분에 한 번 확인하며, 실제 조회에 걸린 시간과 오류 재시도만큼 더 늦어질 수 있습니다. 여러 조건을 한꺼번에 요청하지 않습니다.

**입력 조건 조회**는 현재 입력란의 조건만 한 번 확인합니다. 목록에 자동 추가하지는 않습니다. 수동 조회·중지 후 재개·앱 재실행도 저장된 대기 시간을 지킵니다. 간격을 늘리면 현재 대기도 늘어나고, 줄여도 이미 시작한 대기를 앞당기지는 않습니다.

5분은 앱의 기본 설정이며 대한항공이 보장한 허용 간격은 아닙니다. 확인한 [공식 보너스 항공권 안내](https://www.koreanair.com/contents/booking/reservation-guide/how-to-book/mileage-booking-guide/award-ticket)에는 자동 조회 허용 주기가 없습니다. 5분은 15분보다 전체 조회 빈도가 약 3배 높으며, 조회 한 번에도 달력·항공편 등 여러 웹 요청이 발생합니다. 접근 거부나 요청 제한 응답이 오면 큐 전체를 중단합니다.

새 좌석을 화면·알림음·연결한 텔레그램으로 알립니다. 같은 조건의 같은 좌석은 반복 통지하지 않으며, 정상 조회에서 사라졌다가 다시 나타나면 알립니다. 다른 날짜나 등급의 같은 항공편은 별도 조건으로 판단합니다. 조건을 삭제·변경하면 이전 조건의 아직 보내지 않은 알림도 취소합니다.

앱과 PC가 켜져 있어야 동작합니다. 조회할 때 다른 창에 가려진 전용 Chrome을 앞으로 복원합니다. Chrome이 가려진 상태에서는 화면 갱신을 멈춰 버튼 처리가 지연될 수 있기 때문입니다. 앱을 닫으면 조회가 중지되며, 다시 실행한 뒤 **자동 확인 재개**를 눌러야 합니다. 진행 중 조회는 마무리될 수 있습니다.

## 텔레그램 알림 연결

1. 텔레그램의 공식 [BotFather](https://t.me/BotFather)를 열고 **시작**을 누릅니다.
2. `/newbot`을 보내고 봇 이름, 끝이 `bot`인 영문 사용자 이름을 정합니다.
3. BotFather가 보내 준 토큰을 복사합니다. 앱의 **텔레그램 연결**을 열어 가려진 입력란에 붙여 넣고 **토큰 확인 및 안전하게 저장**을 누릅니다.
4. **내 봇 대화 열기**를 누르고 텔레그램에서 **시작**을 누릅니다. 프로그램으로 돌아와 **연결 확인 · 테스트 알림 보내기**를 누릅니다.
5. 실제로 테스트 메시지가 도착했는지 확인합니다. 이후 **순차 자동 확인**을 시작합니다.

토큰은 봇의 비밀번호입니다. 채팅·소스 코드·설정 파일에 붙여 넣지 않습니다. 앱은 Windows 자격 증명 저장소에 저장하며, 설정 파일에는 연결 대상과 전송 확인 정보만 남깁니다. 연결 링크는 10분 동안 유효합니다. 연결하지 않아도 화면과 알림음으로 사용할 수 있습니다. 봇 생성 방법은 [텔레그램 공식 안내](https://core.telegram.org/bots/tutorial#obtain-your-bot-token)를 참고하세요.

## 로그인 만료와 장애 복구

- 로그인 필요: 감시를 일시 정지하고 텔레그램으로 한 번 안내합니다. **대한항공 창 / 로그인**에서 로그인한 뒤 **자동 확인 재개**를 누릅니다. 스카이패스 번호로 저장했다면 로그인 창에서도 해당 탭을 선택합니다. 앱은 대한항공 비밀번호를 보관하거나 자동 재입력하지 않습니다.
- 통신 장애·조회 중 브라우저 종료: 같은 조건을 5분 뒤, 다시 실패하면 15분 뒤 재시도합니다. 설정한 전체 조회 간격이 더 길면 그 간격을 지킵니다. 실패가 계속되면 큐 전체를 일시 정지하고 알려드립니다. 닫힌 전용 Chrome은 재시도 때 다시 엽니다.
- 결과를 확정할 수 없는 화면: 15분 또는 설정한 간격 중 더 긴 시간 뒤 같은 조건을 한 번 재시도하고, 또 실패하면 큐 전체를 일시 정지합니다. 조건별 마지막 정상 좌석과 확인 시각을 유지합니다.
- 접근 거부·요청 제한: 반복 조회 없이 즉시 중단합니다. 단순 재로그인 문제로 간주하지 않습니다.
- 텔레그램 전송 실패: 미전송 알림을 디스크에 보존하고 1분부터 최대 30분 간격으로 재시도합니다. 앱을 다시 켜도 대기 알림은 유지됩니다. 서버가 받았으나 응답만 유실된 경우에는 중복 전송 가능성이 있습니다.
- 절전에서 복귀: 다음 조건 하나만 수행하고 이후 정상 간격으로 돌아갑니다. 밀린 조건을 몰아서 요청하지 않습니다. 앱 종료 중에는 조회하지 않습니다.
- 지난 출발일: 자동 조회를 중지하고 해당 조건의 날짜 수정을 안내합니다.

## 개발 상태

2026-10-25 기준 자동 검사 65개 통과. 여러 조건의 순환·추가/수정/삭제, 조건별 결과 보존과 알림 분리, 대기 중 재시작, 중지한 조회의 늦은 완료, 로그인 만료 시 큐 정지를 검사합니다.

실제 앱에서 5분 간격으로 일반석 → 프레스티지석 → 일반석 3회 조회에 성공했습니다. 완료 후 다음 시작까지 300.45초, 300.79초였고, 모두 가까운 날짜 조회와 실제 항공편 응답을 확인했습니다. 두 번째와 세 번째 사이 앱을 재시작해 조건 목록·저장 결과·다음 순서·예정 시각이 유지되는 것도 확인했습니다. 이는 짧은 동작 검증이며 장기간의 조회 허용을 보장하지 않습니다.

기존 실사이트 검증: 실제 항공편 조회·텔레그램 수신, 공식 로그아웃을 통한 인증 무효 상태 감지와 재로그인, 15분 간격 3회 정상 조회(약 30분), 전용 브라우저 오프라인 후 5분 타이머 재조회, 브라우저 종료 후 재실행입니다. 알림은 전송 실패를 재현하고 저장 큐를 다시 읽어 실제 재전송까지 확인했습니다.

자연적인 세션 유지 시간, 하루 이상 연속 운전, Windows 잠금·실제 절전 중 동작은 아직 검증하지 않았습니다. 절전 복귀의 조회 중복 방지는 시계를 앞당긴 검사로 확인했습니다. 날짜 범위의 일괄 추가·가족 탑승객은 지원하지 않습니다.

## 로컬 데이터

- `data/`: 전용 Chrome 로그인 프로필, 개인 설정, 마지막 정상 결과, 알림 중복 방지·재시도 기록. Git에 포함하지 않습니다.
- `data/search-queue.json`: 조건 목록, 전체 간격, 다음 순서, 대기 시각, 조건별 마지막 결과. 재실행해도 유지됩니다.
- `work/`: 개발 진단과 실행 상태. Git에 포함하지 않습니다.
- 브라우저는 `127.0.0.1:9335`에만 디버깅 연결을 엽니다.
- 일반 Chrome의 인증정보를 복사하거나 브라우저 보안 설정을 변경하지 않습니다.
- 진단은 허용한 검색 업무 필드만 기록하며 인증 헤더·쿠키·회원정보를 제외합니다.

## 테스트

```powershell
.\.runtime\Scripts\python.exe -m unittest discover -s tests -v
```

테스트에는 로컬 브라우저와 Windows UI 확인이 포함됩니다. 실제 대한항공 조회는 자동 테스트와 별도로 검증합니다. 접근 거부가 발생하면 요청을 자동 반복하지 않습니다.
